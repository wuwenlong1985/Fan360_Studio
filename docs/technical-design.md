# 裸眼 3D 旋转风扇桌面应用：技术方案（评审版）

## 1. 结论摘要

本项目建议采用以下技术栈：

- 桌面容器：Electron + TypeScript
- 渲染层：React + Vite
- UI 组件：Ant Design 5，深色主题
- 3D：Three.js + React Three Fiber + Drei + Postprocessing
- 状态管理：Zustand
- 3D 素材格式：GLB/glTF 为主，程序化场景为辅
- 极坐标转换：Three.js 离屏 RenderTarget + TypeScript 采样/量化模块
- 设备通信：TCP Socket；用户输入设备 IP，端口固定为 5000，用户手动点击连接
- 预览：编辑器圆心预览 + 实际设备圆盘预览 + 360×80 极坐标矩阵预览
- 数据输出：逻辑上生成 360 组角度数据包，打包为 `.fan360` 帧文件或设备传输流

需要先明确的物理边界：

> 单页旋转风扇只能随时间形成一个圆盘平面。它能提供非常强的透视、遮挡、阴影、动态视差和运动模糊效果，但从光学原理上不是真正可环绕观看的体三维显示器。若要求真正多视角体积 3D，需要多层扇叶、多面旋转屏或体素/体积显示硬件。

因此，本方案把目标定义为“单页风扇上实现高质量的裸眼 3D 错觉和惊艳动态效果”，并在 UI 和设备预览中同时显示“编辑视角”和“实际圆盘效果”。

## 2. 已确认硬件参数

| 参数 | 数值 |
|---|---:|
| 风扇页数 | 单页 |
| LED 数量 | 80 个 |
| LED 类型 | 3 色 LED/RGB |
| LED 间距 | 1.5 mm |
| 电机转速 | 1000 rpm |
| 角分辨率 | 1.0° |
| 角度数据组数 | 360 |
| 每个 LED 数据 | 4 字节：亮度 + RGB |
| 单角度片原始数据 | 80 × 4 = 320 B |
| 单圈原始数据 | 360 × 320 = 115,200 B |
| 单圈理论耗时 | 60 ms |
| 每个角度片理论时间 | 166.67 µs |
| 单圈原始数据率 | 1.92 MB/s = 15.36 Mbps |

### 2.1 物理尺寸和坐标定义

建议默认：

- 角度方向：0°..359.9°，每个角度片中心为 `(j + 0.5) × 1.0°`
- 径向方向：80 个 LED 从内到外排列
- 径向采样中心：`r_i = (i + 0.5) × 1.5 mm`
- 最大径向采样半径约 `119.25 mm`
- 物理显示圆盘直径约 `238.5 mm`
- 实际 LED 中心位置和 0° 校准值必须由设备标定，不能写死为假设

### 2.2 内容帧率边界

电机一圈为 60 ms，因此每个角度片在同一圈内只能被点亮一次：

- 每圈重建一次完整图像
- 基础内容更新率上限约为 16.67 fps
- 不能通过软件把单页 1000 rpm 风扇变成真正 60 fps 的全圆盘刷新

可以通过以下方式改善观感：

- 离屏高帧率渲染后做时间平均
- 对运动物体进行运动模糊
- 使用径向/角度超采样后下采样到 360×80
- 用高对比、边缘发光和阴影强化 3D 错觉
- 通过设备双缓冲在下一圈无缝切换画面

## 3. 裸眼 3D 实现策略

单页风扇显示的是极坐标圆盘。三维编辑器和最终显示应分成两条链路：

1. **编辑视角**：摄像机可以环绕、缩放，用户观察完整 3D 场景。
2. **设备投影视角**：场景被投影/采样到 360×80 的圆盘像素矩阵，再生成设备数据。

为了强化裸眼 3D，建议组合使用：

- 透视投影和低角度摄像机
- 物体旋转、摄像机缓慢环绕
- 强环境光遮蔽和接触阴影
- 前后遮挡、景深和轮廓光
- 霓虹边缘、Bloom、辉光和能量粒子
- 多层景深分离，例如主体、背景环、粒子层
- 运动模糊和角度方向拖影
- 透明/半透明材质的层次叠加
- 针对圆盘外的遮罩和黑底处理

必须把这些效果和设备实际效果同时展示，避免编辑器看起来惊艳、设备上却因为 360×80 分辨率或径向间距而完全变样。

## 5. 3D 到圆盘像素的转换管线

### 5.1 管线阶段

```text
场景资产 GLB/程序化场景
        ↓
Three.js 场景渲染
        ↓
离屏 RenderTarget（建议 1024×1024 或更高）
        ↓
读取像素 / GPU 采样
        ↓
按极坐标采样到 360×80
        ↓
颜色空间、Gamma、亮度和色域处理
        ↓
抖动 / 限幅 / LED 可显示性检查
        ↓
生成每个角度片的 [亮度,R,G,B]
        ↓
模拟器预览或设备传输
```

### 5.2 极坐标采样

对每个角度片 `j` 和每个径向像素 `i`：

```text
theta = (j + 0.5) * 2π / 360
radius = (i + 0.5) * 1.5mm

x = cx + radius * cos(theta)
y = cy + radius * sin(theta)
```

再从离屏图像进行双线性采样。编辑器预览可以使用双线性采样；设备预览使用最近邻或带有限滤波的采样，以模拟实际 LED 间距。

### 5.3 颜色处理

建议统一使用线性色空间完成混合、Bloom 和光照，最后再转换到 sRGB/显示空间。每个 LED 输出：

```text
[亮度, R, G, B]
```

其中：

- `亮度` 是该 LED 的主亮度缩放
- `R/G/B` 是线性化并量化后的通道
- 设备端用 PWM 驱动 LED
- 对外协议必须明确字节顺序、Gamma 曲线和重复 Gamma 校正规则
- 如果设备主控只支持 8 bit，建议在桌面端加入蓝噪声抖动，减少低亮度条带

## 6. 360 组数据包格式

### 6.1 逻辑数据组

每个角度片固定包含：

```text
80 × [亮度, R, G, B] = 320 B
```

360 个角度片组成一帧：

```text
360 × 320 B = 115,200 B
```

### 6.2 推荐传输包

为了便于错误检测和设备解析，建议每个角度片增加包头和 CRC：

```text
Magic       2 B
Version     1 B
Type        1 B
Angle       2 B
Sequence    2 B
PayloadLen  2 B
Reserved    2 B
Payload     320 B
CRC32       4 B
----------------
合计        336 B
```

360 个包合计约 120,960 B/圈，原始链路需求约 2.016 MB/s。实际设计应预留至少 30% 链路余量。

### 6.3 推荐设备播放方式

**推荐：整帧预缓冲播放**

1. 桌面端提前上传一帧或多帧。
2. 设备用双缓冲或环形缓冲保存 360 个角度片。
3. 设备读取转子角度/霍尔信号，按照实际角度选择对应角度片。
4. 设备在每个角度片到达时同时刷新 80 个 LED。
5. 下一圈开始时切换缓冲区。

双缓冲至少需要：

```text
115,200 × 2 = 230,400 B
```

推荐使用带 PSRAM/SDRAM 的主控，并保留至少 3 帧缓冲空间用于网络抖动和帧调度。

**TCP 同步策略：同步时暂停显示刷新**

TCP 是字节流协议，不保留消息边界，因此应用层必须使用固定长度的帧头或“消息长度 + 消息体”的封包方式。当前版本采用以下状态机：

```text
用户输入 IP
  → 手动连接 IP:5000
  → HELLO / 能力协商
  → SYNC_BEGIN（帧号、字节数、CRC、超时时间）
  → 设备暂停显示刷新
  → 传输 360 组角度数据
  → SYNC_COMMIT
  → 设备校验 CRC 和长度
  → SYNC_ACK
  → 切换缓冲区并恢复显示
```

由于同步期间设备暂停显示刷新，当前版本不需要在 166.67 µs 内完成网络数据包交付。传输时间取决于 TCP 实际带宽，例如 115,200 B 原始帧在 1 Mbps 链路上约需 1 秒，在 10 Mbps 链路上约需 0.1 秒。

后续如果要求“边同步边显示”，需要增加双缓冲上传协议、帧级确认、断点续传和显示缓冲区原子交换；该问题不在当前阶段实现。
## 7. 已确认的通信与同步约束

目前已确认：

- 设备通信采用 TCP
- 用户输入设备 IP
- 端口固定为 5000
- 必须由用户手动点击连接按钮，不自动连接
- 每个 LED 数据为 `[亮度,R,G,B]`
- 同步 3D 数据期间，设备不执行显示刷新任务
- 同步完成并通过校验后，再恢复设备显示
- “一边同步、一边显示”作为后续独立优化问题，不纳入当前同步协议

仍需硬件方继续确认：

- 实际 LED 驱动和每通道 PWM 位数
- Gamma 曲线
- 0° 参考位置、旋转方向和角度递增方向
- 转子角度传感器类型和抖动
- 设备是否有整帧 RAM、双缓冲和自动播放能力
- TCP 应用层消息格式、最大帧尺寸和超时时间
- 最大链路带宽和传输延迟
- 是否支持 CRC、重传、心跳、掉线恢复
- 亮度是全局亮度、LED 级亮度，还是两者叠加
- 色域标定
- 风扇启动、停止、限速和紧急停机接口

## 9. 关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 单页风扇无法真多视角 3D | 用户体验预期不一致 | 明确“裸眼 3D 错觉”，增加真实设备预览 |
| 1000 rpm 导致内容 16.67 fps | 动画不够流畅 | 运动模糊、超采样、角度方向处理 |
| 360×80 分辨率有限 | 细节丢失 | 大色块、高对比、边缘强化、内容模板 |
| TCP 同步期间暂停刷新 | 同步时设备画面暂停 | 当前版本接受该行为，后续独立解决边同步边显示 |
| 1.92 MB/s 单帧数据量 | TCP 链路传输耗时 | 固定端口 5000，先暂停刷新，再整帧上传和校验 |
| 版权素材 | 无法商用 | 只内置授权/原创素材，支持用户导入 |
| 图片输入模型 | 无法稳定理解截图 | 通过 OCR、图像处理工具和结构化参数辅助 |
| 硬件协议未知 | 无法锁定设备端实现 | 先实现模拟器和可替换 Device Adapter |

## 10. 已确认的产品与通信决策

以下内容已由用户确认：

1. 接受“单页风扇的 3D 错觉”，不要求真多视角体三维。
2. 默认 20 个场景按当前清单执行。
3. 设备通信采用 TCP，用户输入 IP，端口固定为 5000，手动点击连接。
4. 每个 LED 的 4 字节顺序确定为 `[亮度,R,G,B]`。
5. 同步 3D 数据期间暂停显示刷新；同步完成后恢复显示。
6. UI 采用“左侧场景库 + 中央 3D 编辑器 + 右侧参数面板 + 底部时间轴 + 右下设备预览”的主工作台布局。
